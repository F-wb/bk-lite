# 盛大运维系统 · 资源纳管操作手册（服务器/云资源/中间件/K8s/日志）

> **文档用途**：把公司内部服务器与各类资源、服务接入盛大运维系统的**流程主线与操作步骤**（生产 10.10.2.95）。
> 按钮级细节见《盛大运维系统_使用文档》对应篇（02 CMDB / 03 监控 / 05 日志 / 06 节点管理 / 04 告警），本文不重复，只给流程与决策点。
> **最后更新**：2026-11-03

## 0. 纳管总模型（先理解再动手）

**一个底座 + 两条轨道 + 一个台账层**（顺序与依赖关系在此，别搞反）：

```
【底座】接入点（平台自带 fusion-collector 容器）
          一切远程采集 / 远程安装 / JOB 执行的发起者；它不在线 = 自动发现全停摆
          （生产 95 已修复注册：节点 fusion-collector-default，container 类型）

【轨道 A · 主机全能力纳管】—— 装了控制器（Sidecar）才有数据能力
  凭据(SSH/WinRM) → 节点管理装控制器+采集器 → 节点自动注册 + 监控对象推送
      → 指标(VictoriaMetrics) / 日志(VictoriaLogs) / 作业 / 补丁 全能力
      → CMDB 台账：可由「节点管理自动同步」自动建档，也可手工/Excel/自动发现先建
        （节点与 CMDB 资产有 cmdb_id 关联，两边谁先谁后均可）

【轨道 B · 无 agent 纳管（协议/远程）】—— 目标机上什么都不装
  凭据 → CMDB 自动发现采集任务（云平台 API / SNMP / 数据库协议直连 / BMC / K8s apiserver）→ 台账自动建档
  凭据 → 监控集成远程插件（MySQL/RDS/SNMP/WMI/HTTP）→ 由接入点或任一在线采集器【代采】指标

【CMDB 的定位】台账 / 组织层：资产真相源、服务树、视图、权限边界——它本身不产生监控数据。
  没装控制器的机器在 CMDB 里只是清单；装了控制器才有指标/日志/作业能力。
  CMDB 详情页「建立监控关联」只认领已有监控对象（对象是节点管理侧推送的），不新建。
```

**通用前置（一次配好，全局复用）**：

| 项 | 在哪配 | 说明 |
|---|---|---|
| 凭据管理 | 系统管理 → 凭据管理 | SSH / WinRM / SNMP / 云 API 凭据，按**最小权限**建专用账号 |
| 接入点 | 平台自带，无需配置 | 装完基线后必须确认已注册（节点管理 → 云区域 → 节点 有 `fusion-collector-default` 容器节点）；缺失的修复见第 10 节坑速查 |
| 云区域 + 环境 | 节点管理 → 云区域 | 跨网段/跨云不可直连时配**代理地址**（代理机上跑 Nats Executor + Stargazer） |
| 默认节点 | 节点管理 → 云区域 → 节点 | **远程安装控制器必须有一个 nats executor 正常的默认节点**（最常见失败原因） |
| 通知渠道 | 系统管理 → 通知渠道 | 见《生产环境对接操作手册》第 4 节，先通再配告警策略 |

## 1. 资源接入矩阵（对号入座）

| 公司资源 | 纳管方式 | 涉及模块 | 前置物 |
|---|---|---|---|
| 物理服务器 | CMDB 录入/导入；有 BMC 的可用 Redfish 采集（BETA） | cmdb | IP/BMC 只读凭据 |
| **Windows 服务器**（IIS 主机） | WinRM 远程装控制器；主机监控二选一：本机采集器（win_perf_counters）/ **Windows WMI 远程采集**（免 agent） | cmdb / node_mgmt / monitor | WinRM 凭据（管理员级） |
| **SQL Server** | 监控集成 **MSSQL** 预置对象（sqlserver_* 指标），远程连 1433 | monitor | SQL 只读登录名 |
| **IIS** | 监控集成 **IIS** 预置对象（win_iis_w3wp_* 指标，走 Windows 采集器） | monitor | 主机侧采集器在线 |
| **C# 服务**（Windows 服务/进程） | 进程监控（procstat）+ Windows 事件日志策略（服务崩溃 7031/7034） | monitor / log | 主机侧采集器在线 |
| **PVE**（宿主机 + 虚拟机） | 无专用 PVE 驱动：宿主机按 Linux 主机纳管（SSH 装控制器）；VM 按主机/虚拟机模型 Excel 导入 | cmdb / node_mgmt / monitor | SSH 凭据 |
| **阿里云 ECS 实例** | **内置阿里云同步**：CMDB 自动发现 → 采集任务，按 AccessKey 拉取实例清单自动建档 | cmdb | 阿里云 RAM **只读** AK/SK |
| **云数据库**（RDS 等） | 无 agent：CMDB 建数据库实例资产 + 监控集成用 MySQL/PG 插件**远程连接**采集 | cmdb / monitor | RDS 端点放通 + 专用监控账号 |
| **MySQL / Redis / MongoDB / Nginx / ES / PostgreSQL** | 监控集成选对应**预置插件**，绑定 CMDB 资产，预置仪表盘直接可用 | monitor | 专用监控账号（只读） |
| **RabbitMQ** | 监控集成 RabbitMQ 插件（management API 凭据） | monitor | management 端口 + 监控账号 |
| **K8s 集群**（Node/Pod/控制器） | 监控中心 **K8s/K3s 接入向导**：生成 DaemonSet 安装命令 → 集群内应用 → 指标自动上报；CMDB 有 K8S 视图 | monitor / cmdb | kubeconfig / API 地址 + token |
| **Prometheus**（已有监控栈） | 过渡并行：Alertmanager **webhook 告警源**接入告警中心（内置 prometheus adapter） | alerts | Alertmanager 可达平台告警接收地址 |
| **Grafana** | 平台不接管；可选把平台 VictoriaMetrics 当 Prometheus 型数据源加进 Grafana（需网络放通 VM 查询端口） | monitor（被动） | 网络放通 |
| **ELK**（存量日志） | 两条路：① Filebeat/Logstash 转发到平台「**日志接收**」HTTP 端点；② 经 Kafka，日志集成选 **Kafka 采集类型** | log | 端点/Kafka 地址 |
| **二进制部署的服务**（如 Resilio Sync） | **进程监控**：监控集成「进程」对象（procstat 类插件按进程名匹配）+ CMDB 建应用模型挂服务树 | monitor / cmdb | 进程名清单 |
| 网络设备（交换机/防火墙） | CMDB 录入 + SNMP 插件采集（v1/v2c/v3） | cmdb / monitor | SNMP 团体字/凭据 |

### 1.1 自动发现批量建档（CMDB → 管理 → 自动发现，免逐台录入）

逐台手工录入只适合零星资产。批量建档用「自动发现」的两个机制：

- **扫描**：按 IP 段 + 协议（SNMP/SSH）探测摸底，按 OID/特征自动识别设备类型建档——适合**第一次摸家底**；
- **采集任务**：按凭据**持续同步**某类资源的完整清单（主力，可定时跑；重复执行=更新，不是新建）。

公司资源与采集对象对照（对象目录已按源码 `cmdb/constants.py` 核实）：

| 公司资源 | 采集任务对象 | 凭据类型 |
|---|---|---|
| **阿里云** ECS / VPC / RDS 清单 | 云平台 → **阿里云**（一次配好全账户同步） | RAM 只读 AK/SK |
| **K8s 集群**（node/命名空间/工作负载/pod） | 容器 → **K8S** | apiserver 连接凭据 |
| Docker 容器 | 容器 → Docker | 主机 SSH 账号 |
| Linux 主机（含 PVE 宿主机/VM） | 主机逻辑主机 → **主机**（SSH 采 OS/CPU/内存） | SSH 账号 |
| **Windows 主机** | WinRM 凭据采集 | WinRM 管理员凭据 |
| vCenter / ESXi（如有） | 虚拟化 → **vCenter** | vCenter 只读账号 |
| Hyper-V（如有） | 虚拟化 → Hyper-V | WinRM 凭据 |
| **MySQL / PostgreSQL / SQL Server** | 数据库 → 对应协议采集（3306 / 5432 / 1433，MSSQL 为 BETA） | 数据库只读账号 |
| **Redis / MongoDB / ES / Kafka / RabbitMQ / Nginx / Tomcat / Zookeeper / etcd / Consul** | 中间件 → 对应对象（SSH 登录目标机发现采集，Linux） | 主机 SSH 账号 |
| 网络设备 + **拓扑** | NetWork → SNMP（+ Scrapli 配置归档） | SNMP 团体字 / v3 |
| 物理服务器 | 物理服务器 SSH；有 BMC 用 **IPMI**（623）/ **Redfish**（443，BETA） | BMC 账号 |
| 存储设备（华为/Dell/NetApp，BETA） | 存储设备 → 对应 HTTPS API | API 账号 |
| 未知资产摸底 | **IP 发现**（选子网，接入点 ICMP/TCP 探活，回写 IPAM 台账） | 无需凭据 |

**四个提醒**：

1. **接入点必须绑定云区域**（发起采集的容器节点），否则报「当前接入点未绑定云区域」；
2. 首次同步有「等待首次同步完成」状态，属正常；
3. **自动发现只建台账 ≠ 监控上线**——指标/日志采集仍需节点管理装 agent（场景 A 第 3 步起），两件事分开排；
4. **清理策略**：默认不清理（源端删了 CMDB 还在）；新版任务支持「及时清理 / 过期删除」选项，以界面实际为准。

## 2. 场景 A：主机批量纳管（物理机 / PVE 虚机 / 通用 Linux）

**步骤**（CMDB 建档与装控制器**可并行**；但记住：装控制器前，CMDB 记录只是清单，没有数据能力）：

1. **建凭据**：系统管理 → 凭据管理，建专用 SSH 账号（建议禁交互、密钥登录）；
2. **装控制器（Sidecar）**：节点管理 → 云区域 → 节点 → **远程安装**（选默认节点 + Nas Executor 版本）；Windows 走 WinRM（HTTPS=5986 / HTTP=5985，端口协议必须匹配）；
3. **资产入 CMDB**（三选一或组合）：
   - **节点管理自动同步**（推荐）：控制器装好后，节点管理侧会自动把主机同步进 CMDB（"节点管理主机自动采集"任务），免手工；
   - Excel 导入（`02 CMDB` §4.3：只认 xlsx ≤20MiB ≤1 万行，异步任务，先「导出模板」）或手工新增（主机模型先按 IP 建唯一规则防重复）；
   - 自动发现扫描（同网段 SSH 批量探测，需接入点绑定云区域）；
4. **装采集器**：节点详情 → 安装/更新组件（版本匹配 OS + CPU 架构）；
5. **配监控集成**：监控中心 → 集成，绑定资产与主机采集插件，下发后指标进 VictoriaMetrics（<30s 延迟）；
6. **配告警策略**：先用**策略模板 + 策略组**批量绑定（CPU/内存/磁盘套路），上线前每条策略**试运行**验证阈值；
7. **验收**：监控视图 → host 仪表盘能查到该机；故意压测触发一条告警到通知渠道。

**验收标准**：CMDB 台账与实际机器数一致（可用「资产总览」下钻核对）；主机视图 Top N 有数据；至少一条策略试运行通过并真实触发过一次通知。

## 3. 场景 B：阿里云 ECS 实例自动同步

**步骤**：

1. 阿里云控制台建 **RAM 只读子账号**（仅 ECS/List*、Describe* 权限），生成 AccessKey；
2. 系统管理 → 凭据管理：建**平台 API / 云账号**类型凭据，录入 AK/SK；
3. CMDB → 管理 → 自动发现 → **采集任务** → 新增：驱动选**阿里云**，选凭据与**接入点**（须绑定云区域），同步地域可先选 1 个试跑；
4. 首次同步有「**等待首次同步完成**」状态，属正常，等一轮；
5. 验收：资产列表出现 ECS 实例（模型为云账号/实例类），重复执行是**更新不是新建**；
6. 装控制器：云上机器若与平台网络可达，同场景 A 远程安装；不可达则云区域**代理**方案或手动安装。

**注意**：
- 云上已释放的机器默认不会自动消失（**清理策略**默认「不清理」）——需要自动清理就在采集任务里改「及时清理 / 过期删除」，或手工清理；
- AK/SK 是敏感凭证：只读权限 + 只存凭据管理，不落文档。

## 4. 场景 C：中间件与数据库（MySQL / Redis / RabbitMQ / ES / 云数据库 RDS）

**步骤**：

1. **给每个中间件建专用监控账号**（只读；MySQL `GRANT USAGE` 级别即可；RabbitMQ 用 management API 的监控 tag 账号；Redis 建议单独低权限账号并确认 `INFO` 可用）；
2. CMDB 建对应资产（数据库/中间件模型），填连接地址与端口；
3. 监控中心 → 集成 → 新建集成：选**对应插件**（mysql/redis/rabbitmq/elasticsearch/postgres），填凭据与采集参数（间隔）；
4. 集成 → 资产/分组：把配置**挂到 CMDB 资产**；
5. **连通性检测**（`03 监控` §4.9）：这是排查"有资产没数据"的第一站，失败会诊断网络/凭据/插件；
6. 配策略（连接数、慢查询、主从延迟、队列堆积、内存碎片率等按需），先试运行；
7. 验收：监控视图 → 对应仪表盘（mysql/redis/…）有数据。

**云数据库 RDS 专项**：与自建同流程，仅两点不同——① 无 agent，纯远程插件采集；② 需网络放通平台侧（采集器所在节点）→ RDS 端点的白名单。

## 5. 场景 D：K8s 集群接入（Node/Pod/控制器）

**步骤**：

1. 监控中心 → 集成 → **K8s/K3s 接入向导**（支持 K3s 快速接入），填集群连接信息，向导生成 **DaemonSet 安装命令**；
2. 在目标集群执行该命令（kubectl apply）部署采集 DaemonSet（有污点的节点按需补 tolerations 参数）；
3. 用向导的**状态查询**确认采集已上报（Kubernetes 类型需带监控对象）；
4. 仪表盘按 集群 / Node / Pod / Container 维度查看；CMDB 的 K8S 视图同步可见资源；
5. 配策略：Pod 重启/NotReady、Node 压力、容器 OOM 等；
6. 验收：任选一个 Pod `kubectl delete pod` 制造重启，确认监控曲线与告警链路可用。

**日志（可选延伸）**：K8s 容器日志走日志集成的**容器/K8s 采集类型**，由节点管理下发 Vector 采集。

## 6. 场景 E：已有监控栈并行接入（Prometheus / Grafana / ELK）

**定位：平台与存量栈**先**并行**，不强迁、不替换；后续按需逐步收敛。

### 6.1 Prometheus 告警接入（最快见效，先做）

1. 平台侧：告警中心 → 告警来源/接入，启用 **Prometheus 告警源**（内置 adapter），得到接收 URL；
2. Prometheus 侧：Alertmanager 配置 `webhook_configs` 指向该 URL；
3. 触发一条测试告警验证：告警中心收到 → 通知渠道触达；
4. Zabbix 同理（内置 zabbix adapter）。

### 6.2 Grafana（可选）

- 平台不接管 Grafana；存量看板继续用；
- 若想统一：Grafana 添加数据源，类型选 Prometheus，URL 指向平台 VictoriaMetrics 查询接口（需网络放通；自签证书环境注意 TLS 设置）。**先不做也可**，不阻塞主线。

### 6.3 ELK 日志接入（存量日志进平台检索）

两条路按存量架构选：

| 路线 | 做法 | 适用 |
|---|---|---|
| **日志接收（HTTP）** | 平台日志中心 → 集成 → 日志接收，建接收端点；Filebeat/Logstash 输出改为 HTTP 推到该端点 | 量小、改动快 |
| **Kafka 中转** | 存量日志先进 Kafka；日志集成新建采集实例选 **Kafka 类型** 消费 | 量大、已有 Kafka 链路 |

- 原始日志未结构化时配**提取器**（正则/Grok/JSON，用真实样本「运行预览」验证后**保存**触发发布）；
- Java 多行堆栈必配**多行合并**；
- 验收：日志搜索能查到转发样本；配一条日志策略（如 ERROR 频率）验证告警链路。

## 7. 场景 F：二进制部署服务（Resilio Sync 等）进程监控

1. CMDB 建应用/服务模型（或复用既有模型），登记服务清单：进程名、所属主机、负责人；
2. 目标主机已装控制器 + 采集器（场景 A 前提）；
3. 监控集成选**进程监控**（procstat 类插件），按**进程名精确匹配**配置；
4. 视图 → process 仪表盘看进程存活/CPU/内存；
5. 策略两条必备：**进程数 < 1 告警**（挂了）+ **无数据告警**（采集断），先试运行；
6. 验收：停掉某测试进程 → 5 分钟内收到通知。

## 8. 场景 G：Windows 服务器（IIS / SQL Server / C# 服务）

> WinRM 硬约束（`06 节点管理`）：**HTTPS=5986 / HTTP=5985 端口协议必须匹配**；Server 2016+、PowerShell 5.1+；默认 HTTPS/5986 + NTLM，证书校验仅 HTTPS 下可用。HTTP 明文与关闭证书校验仅限可信内网。

### 8.1 Windows 主机纳管

1. **建凭据**：系统管理 → 凭据管理，建 WinRM 凭据（本地管理员或域账号；建议 HTTPS/5986）；
2. Windows 侧前置（每台或域策略统一下发）：
   - `winrm quickconfig` 启用 WinRM；
   - HTTPS 监听需建自签/内部 CA 证书绑定 5986（域环境可用组策略批量）；
   - 防火墙放通 5986（或 5985）；
3. CMDB 建 Windows 主机资产（模型选 Windows 类型，可用 WinRM 自动发现采集批量建档，凭据优先 HTTPS + 证书校验）；
4. **装控制器**：节点管理 → 远程安装（走 WinRM），或按安装指引**手动安装**（WinRM 不通时的兜底）；
5. **装采集器**：节点详情 → 安装/更新组件（Windows 版本包）；
6. **主机监控二选一**：
   - **本机采集**：监控集成 Host 插件走 `win_perf_counters`（Windows 专用输入只在 Windows 节点渲染，不会误下发到 Linux）；
   - **Windows WMI 远程采集**（免 agent）：从采集节点远程 WMI 拉取，适合不便装 agent 的机器；需 WMI 凭据与 DCOM/135 端口放通；
7. 验收：监控视图 → host 仪表盘（Windows 主机）有 CPU/内存/磁盘数据。

### 8.2 IIS 监控

1. 前提：该 Windows 主机采集器在线（8.1 完成）；
2. 监控集成选 **IIS** 对象，绑定该主机资产；
3. 预置指标：`win_iis_w3wp_*`（w3wp 工作进程、HTTP 4xx/5xx、请求量等），视图 → IIS 仪表盘；
4. 策略建议：**应用池停止**（可用事件日志 5074/5186 类事件或进程数策略覆盖 w3wp 消失）、5xx 率、请求队列长度；先试运行；
5. **IIS 访问日志**（可选）：日志集成选**文件**类型，采集 `C:\inetpub\logs\LogFiles\` 下 W3C 日志，配提取器解析字段。

### 8.3 SQL Server 监控

1. SQL 侧建**只读登录名**（SERVER 级 VIEW SERVER STATE 权限，专用于监控），确认 SQL 身份验证可用或用 Windows 账号；
2. 网络放通：采集节点 → SQL Server **1433**；
3. CMDB 建数据库实例资产（IP + 1433 + 实例名）；
4. 监控集成选 **MSSQL** 对象，填连接与凭据，绑定资产 → **连通性检测**；
5. 预置指标：`sqlserver_*`（waitstats 等待、CPU 时间、Re-Compilations 等仪表盘模板）；
6. 策略建议：等待堆积、连接数、磁盘延迟；先试运行。

### 8.4 C# 服务（Windows 服务/进程）监控

按服务形态三选一或组合：

| 方式 | 做法 | 适用 |
|---|---|---|
| **进程监控** | 监控集成「进程」对象按进程名匹配（同场景 F） | 任意进程形态 |
| **Windows 服务计数器** | win_perf_counters 的 Service 对象（本机采集模式） | 以 Windows 服务方式运行 |
| **事件日志策略** | 日志集成选 **Windows Event Log** 类型 → 日志策略匹配 **7031/7034**（服务意外终止）事件 → 告警 | 服务崩溃即时告警（推荐叠加） |

必备策略：服务/进程数 < 1 告警 + 无数据告警；验收 = 停一个测试应用池或服务 → 5 分钟内收到通知。

## 10. 通用坑速查（细节见使用文档 FAQ）

| 现象 | 根因 | 处理 |
|---|---|---|
| 远程安装控制器失败 | 默认节点 nats executor 不正常 | 换/修默认节点（最常见） |
| 采集任务「接入点」下拉为空 / 节点管理自动采集被阻塞 | 安装器不生成 `SIDECAR_INIT_TOKEN`/`SIDECAR_NODE_ID`，fusion-collector（接入点）sidecar 注册失败（`FATAL: No API token was configured`）；或节点组织与当前用户团队不交叉 | 修复：server 容器 `python manage.py node_token_init --ip <本机IP>` → node_id+token 写 `.env` → `up -d --force-recreate fusion-collector`（95 已修，2026-11-03）；再核对节点组织与登录团队对齐 |
| 主机有资产但监控无数据 | 采集器离线 / 集成未配 / 未绑定 | 按 03 监控 §7 链路排查，先跑「连通性检测」 |
| 阿里云同步后机器删了 CMDB 还在 | 清理策略默认「不清理」 | 任务里改「及时清理/过期删除」，或手工清理 |
| 导入提交了没数据 | 导入是异步任务 | 去「导入导出记录」看状态 |
| 同一机器两条记录 | 模型未建唯一规则 | 按 IP 建唯一规则后合并 |
| 策略阈值填 50 按 0.5% 判 | percent / percentunit 单位选错 | percent=0–100，percentunit=0.0–1.0 |
| 提取器配了不生效 | 只「仅保存」未发布 / Vector 未拉取 | 点「保存」触发发布，看发布状态 |
| Prometheus 告警收不到 | Alertmanager webhook 指向错误 / 平台侧来源未启用 | 两端各发一条测试验证 |
| Windows 装控制器报端口不匹配 | WinRM 协议端口配对 | HTTPS=5986 / HTTP=5985 |
| Windows WMI 远程采集不通 | DCOM/WMI 端口未放通或凭据权限不足 | 放通 135 + 动态端口，或改本机采集器方案 |
| 云上机器装不了控制器 | 网络不可直连 | 云区域代理 或 手动安装 |
