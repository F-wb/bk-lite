# 盛大运维系统 使用文档 · 05 日志中心

> 模块标识：`log`　|　顶部导航入口：**日志中心**
> 日志中心负责"把日志收上来、存起来、查得动、按内容告警"。采集由 Vector 完成（依赖节点管理下发），日志存于 VictoriaLogs；提取器把非结构化日志转成结构化字段，日志策略可推送到告警中心。
>
> 本篇按钮与提示文案取自前端源码 `log/locales`。

---

## 1. 功能概述

- **日志搜索**：全文/字段检索、时间直方图。
- **日志分析**：在结果上做统计。
- **事件**：日志告警（告警 + 策略）。
- **集成**：日志采集（日志集成）、日志接收、日志分组。

---

## 2. 入口与前置条件

- 入口：顶部导航选择「日志中心」。
- **前置条件**：目标主机/容器有在线 Vector（`06 节点管理`）→ 建"日志集成"采集实例 → 需要结构化字段时配提取器。
- 若在日志详情里点"创建提取器"提示 **「这条日志没有采集实例，无法创建提取器」** 或 **「找不到这条日志所属的采集实例，或当前团队无权编辑其提取器」**，说明该条日志没有归属的采集实例/无权限，要先到「日志集成」确认。

## 4. 核心操作流程（按钮级）

### 4.1 配置日志采集（日志集成）

1. 「集成 → 日志集成」→ 新建采集实例，选**采集类型**：文件、Syslog、Kafka、HTTP、容器/K8s、Journald、Windows Event Log。
2. 指定目标主机/范围；采集配置由节点管理下发到 Vector。
3. 进入实例内页签：
   - **配置**：采集来源与参数（含多行合并，见 4.3）；
   - **提取器**：字段提取规则（见 4.2）；
   - **简介/输出**：输出与写入信息。
4. 采集实例可启停；采集结果实时写入 VictoriaLogs。

### 4.2 配置日志提取器（把日志变结构化）

1. 在采集实例的「提取器」页点 **「新建提取器」**（编辑用「编辑提取器」）。
2. 选择解析方式并填规则：
   - **正则**：界面提示 **「至少需要一个命名捕获组，例如 `(?P<status>\d+)`，捕获组名就是写出的字段名。」**
   - **Grok / JSON**：按对应语法填。
3. **字段映射**（`字段映射（JSON 对象，可空）`）：
   - **targetField**（JSON）：**「可空。填写后把解析出的对象写入该父路径，留空则合并到事件根。」**
   - **targetField**（普通）：**「可空。填写后写入该字段，留空则覆盖源属性。」**
   - 映射必须是"目标路径均为字符串的 JSON 对象"，否则报 **「映射必须是目标路径均为字符串的 JSON 对象」**。
4. **用真实样本验证**：点 **「选择一条历史日志」** 选样本 → 点 **「运行预览」**：
   - 结果展示 **「预览结果」**、**「相对所选样本的字段变化」**；
   - 状态：**「提取成功」/「提取失败」/「条件未命中」**；
   - 样本读取失败可 **「重试」**（**「历史样本读取失败，可重试；不影响规则编辑和保存。」**）。
5. 保存有两种：**「保存」**（保存并触发发布）与 **「仅保存」**（只存不发布）。
6. **发布状态要看懂（关键）**：
   - 状态：`等待发布 / 已发布 / 发布失败`；
   - **「仅表示 Server 已发布，不代表 Vector 已拉取或生效。」**——所以"已发布"不等于线上立刻按新规则解析；
   - 失败时可 **「重试发布」**（提示「已提交发布重试」）；
   - 失败期间说明：**「规则已保存，但全局配置发布失败。当前运行环境继续使用上一份有效配置。」**
   - 该状态是**全局状态**，可能受其他采集实例规则变更影响。
7. 若一条提取规则都没有，界面提示 **「暂无提取规则，日志会保持原样进入 VictoriaLogs。」**

### 4.3 配置多行合并（Java 堆栈/多行日志必用）

在采集配置里设置"条件模式"，三种模式界面含义（原文）：

| 模式 | 含义 | 适用场景 |
|------|------|----------|
| **一直合并直到遇到符合条件的行（但不包含这行）** | 看到新日志的时间戳就停止，时间戳属于下一条 | 新日志**有明确开头标记** |
| **持续合并所有符合条件的行，直到遇到不符合的行** | 如 Java 报错堆栈中所有以空格开头的行合并到上一条 | **有明显"附属行"特征** |
| **合并到第一个符合条件的行（包含这行）** | 如日志以分号结尾时把带分号的行也并入 | **有明确结束标记** |

- **起始行正则**用于识别"新日志条目的起点"，界面给了典型场景：Java 用时间戳/级别、Docker 匹配 `[2023-10-01]` 前缀、SQL 识别 `SELECT` 等关键字。
- **合并超时**（毫秒）说明：**「定义了系统在等待下一条匹配行时的最长等待时间。当超过这个时间阈值后，即使当前日志消息不完整，缓冲区的内容也会被强制刷新输出。」**
- 附加条件：**「空条件表示该作用域内全部事件。」**；条件属性、操作符、比较值三者不能为空。

### 4.4 搜索日志（日常最常用）

1. 「日志搜索」输入关键字或条件；可用 **「附加条件」** 加字段过滤。
2. 结果列表高亮关键词、显示时间戳与提取字段；上方直方图看分布。
3. 可保存常用搜索条件跨会话复用。

### 4.5 日志分组与权限

- 「集成 → 日志分组」按业务/主机/标签归类采集实例；同组可统一检索。
- 分组承载**组织/团队权限**：不同团队只看自己归属的日志组。

### 4.6 日志告警（事件 → 策略）

1. 「事件 → 策略」新建：匹配条件（关键字/正则）+ 频率阈值 + 时间窗口。
2. 满足频率即生成告警事件推送到**告警中心**（含匹配日志样本）。
3. 「事件 → 告警」查看日志侧告警；告警产生时保存日志原文快照（含上下文）。

### 4.7 接收外部日志

- 「集成 → 日志接收」配置接收端点，供外部系统主动推送日志。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 正则提取 | 必须有命名捕获组，组名=字段名 |
| 字段映射 | JSON 对象；填父路径则挂其下，留空并入根 |
| 保存 vs 仅保存 | 「保存」会触发发布；「仅保存」只存 |
| 发布状态 | 已发布 ≠ Vector 已生效 |
| 多行合并 | 三种条件模式，按日志形态选 |
| 合并超时 | 超时强制刷新缓冲，避免半条日志卡住 |
| 空条件 | 表示作用域内全部事件 |

## 6. 权限要求

- 搜索/查看：一般运维，受日志分组组织权限约束。
- 配置采集集成、提取器、告警策略：需"日志管理员"角色。
- 提取器按采集实例的团队归属授权（无权会提示"当前团队无权编辑其提取器"）。

## 7. 常见问题（FAQ）

**Q：配了采集但搜不到日志。**
A：① Vector 是否在线（`06 节点管理`）；② 采集类型/路径/端口是否正确（文件是否存在新行）；③ 采集实例是否启用；④ 写入有延迟，稍等再搜。

**Q：提取器配了，搜索里没有结构化字段。**
A：① 规则是否**发布**（只"仅保存"不生效）；② 发布状态是否"已发布"——注意"已发布只代表 Server 侧，Vector 可能还没拉取"；③ 用「运行预览」贴样本确认能提取成功。

**Q：多行 Java 堆栈被拆成很多条。**
A：配多行合并：起始行正则用时间戳/级别，模式选"持续合并所有符合条件的行"（空格开头的附属行并到上一条）；必要时调小合并超时。

**Q：发布失败怎么办。**
A：点「重试发布」；失败期间线上仍用上一份有效配置，不影响现有采集。若反复失败，看是否为全局配置问题（状态是全局的，可能受其他实例规则影响）。

**Q：点创建提取器提示"没有采集实例"。**
A：该条日志不属于任何采集实例，或当前团队无权编辑。先到「日志集成」确认归属与团队权限。

**Q：搜索很慢/超时。**
A：缩小时间范围、加字段过滤减少命中；避免超大范围纯通配全文扫描。

**Q：不同团队想只看自己的日志。**
A：用「日志分组」按团队归类并设组织归属，权限自动隔离。
