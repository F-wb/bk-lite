## 1. 功能概述

「集群管理」用于在浏览器里查看和操作 Kubernetes 集群：看集群列表与详情、看节点与命名空间、看资源对象、
查日志审计、管理镜像仓库。它替代的是"SSH 到 master 记 kubectl 命令"这条路，**不替代发布**。

一句话定位：**看和应急用它，发布不用它。**

## 2. 入口与前置条件

| 项 | 内容 |
|---|---|
| 入口 | 平台顶部「控制台」宫格 → 卡片 **「集群管理」** |
| 打开方式 | **新标签页**打开对方地址（外部应用的固有行为，不是故障） |
| 登录 | **需单独登录一次**。界面标题为 **「登录 KubePi」**。与平台是两套账号体系，**没有单点登录** |
| 首次登录 | 若账号仍是出厂口令，界面会要求 **「修改默认密码」**（需填「确认密码」）。改完才能继续 |
| 语言 | 界面为中英双语，同一入口两种文案并存（如 `创建 / Create`） |
| 看不到卡片 | 两种原因：① 你的角色未被授予该应用的权限；② 管理员尚未在「应用管理」登记/启用（见《01 系统管理》§4.7） |
| 卡片点开报错 | 先确认对方服务本身活着（平台侧一切正常时，本模块挂掉**不影响平台任何功能**） |

## 4. 核心操作流程

### 4.1 进入某个集群

宫格点「集群管理」→ 新标签页 → 「登录 KubePi」→ **集群列表** → 目标集群行点 **「详情」**。
要看配置项而非只看状态时点 **「编辑集群信息」**（改这里会影响连通性，非运维请勿动）。

### 4.2 导入新集群（运维操作）

**集群列表** → **「导入集群」** → 填名称 → 粘贴 kubeconfig（界面字段名 `kubeconfig 文件`）→ **「确定」**。

注意：kubeconfig 内容会被**加密存入面板自己的库**，平台不持有任何集群凭据；因此
**平台备份里没有它**，它只存在于面板数据卷与面板快照里（边界见 §7）。

### 4.3 浏览资源与查看留痕

- 左侧进入 **资源 / 节点 / 命名空间** 查看对象；筛选用 **「查询」**。
- 排障时先到 **日志审计 / 操作日志** 看"谁在什么时候做了什么"（字段含操作人、登录 IP、登录城市）。
  面板的操作留痕**只覆盖面板内的动作**，平台侧动作不在这里，反之亦然。

### 4.4 工作负载类操作（已实测 2026-11-09，于 121 v1.36.5 只读取证）

面板的操作按钮集中在每个对象行末尾的“更多⋮”下拉里（行首另一个图标是“详情”）。实测到的**面板原文**如下（列名以中文为准，同一词表另有英文）：

| 日常动作 | 面板按钮原文 | 出现在哪类对象 |
|---|---|---|
| 进入容器（Web 终端） | **终端** | Pod 行下拉 |
| 查看日志 | **日志** | Pod 行下拉 |
| 重启 / 滚动重启 | **重启** | Deployment / StatefulSet 行下拉 |
| 扩缩容 | **伸缩** | Deployment / StatefulSet 行下拉（顶部工具栏同名，多选时生效） |
| 查看 / 编辑 YAML | **编辑 YAML**（工作负载）/ **下载 YAML**（Pod） | Deployment / StatefulSet 行下拉有“编辑 YAML”；**Pod 行下拉只有“下载 YAML”** |
| 改镜像版本 | **修改镜像版本** | Deployment / StatefulSet 行下拉 |
| 删除 | **删除** / **强制删除**（Pod） | 各对象行下拉；顶部工具栏也有“删除” |

- **Pod 行下拉完整项**：终端 / 日志 / 文件浏览器 / 下载 YAML / 删除 / 强制删除。
- **Deployment 行下拉完整项**：伸缩 / 修改镜像版本 / 重启 / 编辑 YAML / 下载 YAML / 删除。

⚠️ **上述按钮都点得动，不代表允许在生产集群上点**。重启/伸缩/改镜像/编辑 YAML 属写操作，生产变更一律走流水线（见 §5 红线）。本模块的正确用法是**观察与应急**，不是发布通道。

## 5. 使用红线（界面能做，不代表可以做）

| 禁止 | 原因 |
|---|---|
| **在生产集群改镜像版本 / 编辑 YAML** | 会造成「集群实际状态与 git 不一致」的永久漂移，回滚不可靠。生产发布只走流水线打 tag |
| 把面板当第二条发布通道 | 与 `values-<环境>-<集群>.yaml` 规范和服务器端快照归档区冲突 |
| 在测试集群用了「编辑 YAML / 改镜像」却不回灌 | 必须在 24 小时内把差异合回 values，并在归档区补一条说明 |
| 引用 `latest` 类镜像版本 | 无论面板里还是 values 里，一律显式版本号 |

红线是流程约束，**不是本模块的能力边界**——界面上的按钮点得动，不代表允许点。

## 6. 常见问题

**Q：为什么点进来还要再登录一次？**
A：它的外部应用身份决定的，界面上是独立标题「登录 KubePi」。平台与它**没有做单点登录**，这是既定现状而非待修故障。

**Q：提示「此操作不可撤销，是否继续？」要不要点？**
A：这是删除类动作的二次确认原文。**在生产集群上见到这句就该停手**——删除生产对象请走既定变更流程。

**Q：改了「集群管理」的地址，宫格还跳旧地址。**
A：属预期。宫格卡片是每人一份快照，外部应用不回表刷新。需管理员改应用记录**并**重建相关用户的卡片集合（见《01 系统管理》§4.7）。

**Q：面板里某个页面报错，是不是面板坏了？**
A：先分集群。已纳管集群中有一个 Kubernetes 版本**低于该面板官方支持区间**（详见台账 DEV-1）。
**先把同一操作在另一套集群上试一遍**：只在某一集群出错，基本可以排除面板故障。

**Q：这里能看 Pod 日志，还要平台日志中心干什么？**
A：面板看的是**当前对象的实时日志**；平台日志中心负责**采集、留存、检索、告警**。历史查询与告警一律回平台。

## 7. 数据边界（出问题时该找谁）

| 问题 | 找哪边 |
|---|---|
| 面板里的集群连不上、kubeconfig 失效 | 面板侧（凭据只存在面板库里） |
| 面板口令/账号被锁 | 面板侧管理员 |
| 宫格没有入口、权限没生效 | 平台侧「应用管理」（《01 系统管理》§4.7） |
| 面板数据要不要备份、怎么还原 | **不在平台备份范围内**，由独立任务负责；见 `ops/kubepi/README.md` 与部署手册第八章 |
| 版本、已纳管集群清单、变更史 | `docs/kubepi/版本与变更台账.md` |
