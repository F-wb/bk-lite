# 盛大运维系统 使用文档 · 04 告警中心

> 模块标识：`alerts`　|　顶部导航入口：**告警中心**
> 告警中心是全平台的"事件处置中枢"：把监控、日志、外部系统（Prometheus/Alertmanager、Zabbix、HTTP 推送、SNMP Trap）的告警统一接入，做富化、聚合降噪、分派、通知，并支持事故协同与自动恢复关闭。
>
> 本篇按钮与提示文案取自前端源码 `alarm/locales`，按此可对上界面。

---

## 1. 功能概述

- **事故（Incident）**：把相关告警聚合成事故，多人协同、IM 群同步、关闭归档。
- **告警（Alarms）**：单条告警的认领/分派/关闭/屏蔽/升级为事故。
- **集成**：接入外部告警源。
- **配置**：相关性规则、告警分派、通知模板、屏蔽策略、告警丰富、告警处理、执行记录、全局配置、操作日志。

---

## 2. 入口与前置条件

- 入口：顶部导航选择「告警中心」。
- 通知渠道需先在「系统管理 → 通知渠道」配好；否则界面会提示 **「没有可用于建群的渠道，请先前往系统管理配置。」** 或 **「暂无通知渠道，可去…」**。
- 外部告警接入需在对端（Alertmanager/Zabbix/自定义脚本）配好指向本系统的推送地址与凭证。

## 4. 核心操作流程（按钮级）

### 4.1 值班处置一条告警（最常见）

1. 「告警」列表筛选待处理项（状态：`未分派 / 已恢复 / 已关闭` 等）。
2. 选中告警点 **「认领」**（列表行内也有 **「认领」**）：告警**处理人**变为你，状态转为处理中。
3. 若不该你处理，用 **「分派」** 指定 **「处理人」**。
4. 排查完后点 **「关闭此告警」**：
   - 弹窗可填 **「关闭原因（选填）」**，占位提示 **「请输入关闭原因」**；
   - 关闭成功提示 **「关闭成功！」**，状态变为 **「已关闭」**，记录 **关闭时间**。
5. **恢复类**：若来源发了恢复事件且启用了自动恢复，告警会显示 **「已恢复」**；再按策略 **「自动关闭」**。
6. 需要多人协同的复杂问题，点 **「升级为事故」** 转成 Incident（见 4.5）。

> 所有认领/分派/关闭/屏蔽动作都写入「配置 → 操作日志」，不可篡改。

### 4.2 配置告警分派（谁来处理）

「配置 → 告警分派」说明原文：**「您可以配置自动分派策略，将符合条件的告警分派给指定用户或组织，并选择通知方式。」**

1. 新建分派策略：设**匹配条件**（组织/团队/标签/级别）、**目标处理人**、**通知方式**。
2. 规则按优先级匹配，未命中走默认分派人。
3. 策略可绑定通知模板（见 4.3），界面会显示 **「已绑定 {count} 个分派策略」**，点 **「去告警分派」** 可跳转关联。
4. 支持超时升级：到点未认领自动上报上级并提级别（在分派/全局配置里设阈值）。

### 4.3 配置通知模板（发成什么样）

「配置 → 通知模板」说明原文：**「一个模板组代表一种业务用途，可同时维护邮件 HTML 和企业微信 Markdown；在告警分派策略中可按通知渠道和告警场景选择使用哪个模板组。」**

1. 点 **「新建通知模板」**，填 **「模板组名称」**。
2. 选择 **「包含的渠道版本」** 后分别编辑（官方规则）：
   - **邮件 → HTML**
   - **企业微信群机器人 / 钉钉 / 飞书 / IM 应用通知 → Markdown**
   - **企业微信应用消息 / Webhook / OpsPilot → 文本**
3. 编辑时可 **「核对渲染后的关键变量，确认只展示当前真实可配置项」**（即用真实变量预览，避免写错占位符）。
4. 保存后到分派策略里引用。
5. 投递失败会重试（最多 3 次），恢复通知走同一渠道发给原接收人。

### 4.4 聚合降噪（相关性规则）

「配置 → 相关性规则」用**条件组**表达逻辑，界面提示原文：
- **「同一条件组内须满足全部条件（且）；多个条件组满足任意一组即可（或）。」**
- 按钮：**「添加条件（且）」**、**「添加条件组（或）」**，以及 **「删除条件」/「删除条件组」**。
- 字段填写要点（原文）：
  - **级别**：下拉多选，匹配事件/告警级别；
  - **告警源**：多选集成源，可搜名称/ID/接入标识，**按最新来源去重、排除恢复事件**；
  - **监控源**：与告警聚合的监控源集合比较；**「匹配任一监控源即可；否定条件须全部不匹配。无监控源时不命中。」**
  - **标识**：输入完整类型或实例标识，回车添加多个；**「001 与 1 不同」**（按字符串精确比）；
  - **标签**：回车确认，自动去首尾空白与重复；**「逗号是值的一部分，不自动拆分」**；**最多 50 个候选值，每项≤256 字符**；
  - **空值**：**「字段缺失、空文字或空集合均不命中，不等于、不包含等否定条件也一样。」**
- 聚合结果合并为一条，成员告警可展开；窗口超时自动输出，异常时放行原始告警不丢失。

### 4.5 事故协同（Incident）

1. 「事故」→ 新建，或在某条告警上点 **「升级为事故」**：
   - 弹窗支持**关联模式**加入已有 Incident（提示：**「可通过'升级为事故'弹窗中的关联模式加入已有 Incident」**）；
   - 系统按**时间窗口（仅推荐最近 1 小时内发生的告警）**给出可归并推荐。
2. 填 **「事故名称」**、级别、处理人；处理人需先选**渠道**再选已映射的 Incident 负责人（**「请先选择渠道，再选择已映射的 Incident 负责人」**）。
3. 事故可开启 **IM 群同步**：
   - 暂停同步 → **「暂停后，后续加入 Incident 的人员不会自动进入 IM 群；当前群和已入群成员不受影响。恢复时将立即补拉待处理人员。」**
   - 恢复同步 → **「恢复后将立即检查并同步全部待处理人员。」**
   - 可 **「重试全部待处理人员」**；关闭群同步时要输入当前群名称确认。
4. 事故详情按时间线展示关联告警与进展更新，支持多人协作。
5. 关闭事故后按原配置可恢复（**「重新打开 Incident 后按原配置恢复」**）。

### 4.6 屏蔽策略（临时静音）

1. 「配置 → 屏蔽策略」新建：范围（告警源/主机/标签）+ 时间窗口 + 级别。
2. 屏蔽期间**告警仍记录、只是不发通知**，到期自动解除。
3. 单条告警也可直接点 **「屏蔽」** 做临时静音。

### 4.7 接入外部告警源

1. 「集成」新建告警源，选类型（监控/日志/HTTP 推送/SNMP Trap/Prometheus Alertmanager/Zabbix）。
2. 填接入参数与凭证，系统分配唯一标识；把接收地址填到对端。
3. 数据流：校验来源 → 解析 → 标准化 → 富化。无效格式进错误日志。

### 4.8 告警丰富（富化）

- 「配置 → 告警丰富」定义规则链：匹配条件 + 动作（补 CMDB 资产信息、加标签、设优先级）。
- 多条**按序链式**执行，前一条结果喂给后一条；CMDB 查询失败**熔断放行**，不阻塞告警。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 关闭原因 | 选填，便于复盘 |
| 条件组 | 组内"且"，组间"或" |
| 标签候选值 | 最多 50 个，单个≤256 字符，逗号不拆分 |
| 空值规则 | 缺失/空串/空集合都不命中 |
| 标识比较 | 按字符串精确，"001" ≠ "1" |
| 模板渠道版本 | 邮件HTML / 企微钉钉飞书Markdown / 企微应用Webhook文本 |
| 事故推荐窗口 | 仅推荐最近 1 小时内告警 |
| 屏蔽 | 记录但不通知，到期自动解除 |

## 6. 权限要求

- 值班处置（认领/分派/关闭/屏蔽/升级事故）：值班/运维角色，受数据权限限制。
- 配置（集成/相关性/分派/模板/屏蔽/富化/告警处理）：需"告警管理员"角色。
- 建群/渠道：依赖系统管理通知渠道配置。

## 7. 常见问题（FAQ）

**Q：外部系统告警进不来。**
A：查——① 集成来源类型与参数；② 对端推送地址/凭证；③ 操作日志/错误日志有无"无效事件格式"；④ 是否被屏蔽策略命中。

**Q：告警风暴，一小时几百条同源。**
A：配「相关性规则」用条件组（组内且、组间或）按主机+指标聚合；同时检查监控侧阈值是否过敏、是否缺持续时间。

**Q：维护窗口不想被告警刷屏。**
A：用「屏蔽策略」按主机/标签设时间窗；屏蔽期仍记录，到期自动恢复。

**Q：没人认领会怎样？**
A：配了超时升级就会自动上报并提级别；在「告警分派」/全局配置设阈值。

**Q：通知没收到。**
A：① 系统管理渠道连通性；② 模板渠道版本是否与渠道匹配（邮件要HTML、企微群机器人要Markdown）；③ 变量预览是否正常；④ 投递记录/重试；⑤ 是否被屏蔽。

**Q：告警恢复了还挂在活跃列表。**
A：来源需发恢复事件；开启「自动关闭」后恢复事件会关闭并通知。

**Q：想合并已有事故而不是新建。**
A：用「升级为事故」弹窗的**关联模式**加入已有 Incident；系统只推荐最近 1 小时内的告警便于归并。

**Q：相关性规则配了但没生效。**
A：常见是**分组维度/监控源选错**导致"无监控源时不命中"，或标识用了 `1` 想匹配 `001`（按字符串精确，不相等）。逐项核对条件组。
