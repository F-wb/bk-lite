# 盛大运维系统 使用文档 · 10 二开功能

> 本篇覆盖在开源基线之上做的三项定制：**品牌定制、钉钉企业登录、JumpServer 堡垒机 SSH 终端**。
> 这三项是"盛大运维系统"区别于原版的地方。日常使用主要涉及后两项；品牌由管理员统一维护。

---

## 1. 品牌定制（界面显示为"盛大运维系统"）

### 1.1 用户可见效果

- 登录页、顶部导航、浏览器标签标题均显示 **「盛大运维系统」**，Logo 为定制图标。
- 水印功能**默认关闭**（当前交付配置 `watermark_enabled=0`，不显示水印）。

### 1.2 管理员：修改品牌配置

品牌名、Logo、水印不是改代码，而是走**数据库配置**（前端从后端读取后运行时注入）：

- 配置项（`系统设置`）：
  - `portal_name`：站点名称（当前 = 盛大运维系统）
  - `portal_logo_url` / `portal_favicon_url`：Logo 与浏览器图标地址；**留空则回退默认 `/logo-site.svg`**
  - `watermark_enabled`：水印开关（`1` 开 / `0` 关）
  - `watermark_text`：水印文案模板（如 `盛大运维系统 · ${username} · ${date}`，仅在开关为 `1` 时生效）
- **启用水印**：把 `watermark_enabled` 置为 `1` 并刷新页面即可（文案模板已保留）。
- **换 Logo**：上传新图后把 `portal_logo_url`/`portal_favicon_url` 指向它；支持 `.svg`（按后缀自动判定 MIME）。

> **排障提示**：请求 `/favicon.ico` 返回 404 是**正常现象**——图标由前端按配置 URL 运行时注入，不走 `/favicon.ico`。判断品牌是否生效，看"配置值正确 + 其指向文件能 200 访问"，不要以 `/favicon.ico` 为准。

## 2. 钉钉企业登录

让用户使用钉钉扫码/授权登录平台，免去单独记平台密码。需管理员先配置、用户才能真正用起来。

### 2.1 管理员配置步骤

1. **准备钉钉应用**：在钉钉开发者后台创建应用，拿到 **App Key / App Secret**；开通接口权限：
   - `Contact.User.Read`（必需）
   - `Contact.User.mobile`（按手机号匹配账号时必需）
2. **集成中心创建钉钉实例**：进「系统管理 → 集成中心」→ 点新建/添加集成 → 类型选**钉钉**，进入集成详情填写：
   - **App Key / App Secret**
   - **企业代码 Corp ID**：个人/测试应用**留空**；仅企业内部应用单点登录时填真实 `dingxxxx`
3. **登录认证绑定**：进「系统管理 → 用户管理 → 登录认证」→ 新增绑定 → 选中上一步的钉钉实例 → 配置**字段映射**：
   - 推荐：平台字段 **手机号(phone)** ← 外部字段 **mobile**（按手机号匹配已有账号）；
   - 或：平台字段 **用户名(username)** ← 外部字段 **open_id**（测试用，未匹配到则自动建号）。
   若提示「集成实例已禁用」/「集成实例的登录认证能力已禁用」，先回集成中心启用该实例及其登录认证能力。
4. 保存后，登录页出现「钉钉」登录标签。
5. 更详细的对接操作见《盛大运维系统_钉钉登录对接操作手册.md》。

### 2.2 用户使用步骤

1. 打开登录页，切换到「钉钉」标签。
2. 用钉钉 App 扫码或在钉钉内授权。
3. 系统按手机号匹配到你的平台账号并自动登录。

### 2.3 常见问题

- **扫码提示匹配不到账号**：你的钉钉手机号与平台账号手机号不一致。请管理员在「用户管理」把你的手机号补成与钉钉一致，或改用 open_id 自动建号方式。
- **授权页报 `clientId is blank` / `token is missing`**：属已知历史问题，交付版本已修复；若复现，联系管理员核对钉钉应用凭证与权限开通。
- **提示"没有调用该接口的权限"**：钉钉后台未开通 `Contact.User.Read`。

## 3. JumpServer 堡垒机 SSH 终端

在 CMDB 资产详情页点一下「SSH 终端」按钮，就能直接打开堡垒机（JumpServer Luna）的网页终端连上那台机器，不用单独登录堡垒机再找主机。

### 3.1 管理员配置步骤

1. **集成中心创建 JumpServer 实例**：「系统管理 → 集成中心」新建 JumpServer Provider，填：
   - **base_url**：用 **https** 地址（JumpServer 对 80 端口强制跳 443），**不含结尾斜杠**
   - **verify_ssl**：JumpServer 用**自签名证书时关闭**（默认开启）
   - **API Key / API Secret**：须为 JumpServer **超管账号**在「个人设置 → API Key」生成的凭证（需具备建用户、查资产、发令牌权限）
   - **default_system_user**：默认登录系统账号（如 `root`）
   - **Token 过期时间**（默认 3600 秒）、**自动创建用户**（默认开启）
2. **JumpServer 侧前提**：目标主机资产已存在于堡垒机，且**资产的 `address` 或 `name` 与 CMDB 主机 IP 一致**，并已配置 SSH 协议的系统账号。

### 3.2 用户使用步骤

1. 进入「配置管理 → 资产」，打开一台**含 IP 的资产详情**（host、虚拟机等；IPAM 网段不支持）。
2. 在详情页 **「基础信息」** 页签右上操作区，点 **「SSH 终端」** 按钮（位置在 **「订阅」** 与 **「批量编辑」** 之间；需 Edit 权限才显示）。
3. 系统在**新浏览器标签页**打开 JumpServer Luna 终端，自动连上该主机。

> 为什么是新标签页而不是内嵌窗口：终端会话依赖堡垒机的登录 Cookie，跨站内嵌 iframe 无法携带该 Cookie，因此改为顶层新标签页打开，确保会话可用。首次使用若堡垒机未登录，会先在堡垒机完成登录。

### 3.3 资产匹配规则（重要）

系统用 CMDB 主机的 **IP** 去堡垒机匹配资产，匹配顺序：

1. 先按资产 **`address` 精确相等**；
2. 未命中再按资产 **`name` 精确相等**；
3. 都匹配不到则报 `Asset with IP or name {ip} not found`。

**网关端口映射场景**（堡垒机不能直连目标内网、需经宿主机端口映射时）：
> 例：Windows 宿主机 `10.10.40.81` 用 VMware 把 `2222` 映射到虚拟机 `192.168.1.11:22`。
> 堡垒机侧应把资产 **`address` 填宿主机 IP `10.10.40.81`**、**`port` 填映射端口 `2222`**（填 `192.168.1.11` 堡垒机路由不到）；同时把资产 **`name` 命名为 CMDB 里的主机 IP `192.168.1.11`**，即可被正确命中。

### 3.4 常见问题

- **点 SSH 终端报 401 / token 无效**：平台登录态问题（已随交付修复：请求会带上平台 token）。若复现，重新登录平台再试。
- **提示找不到资产**：按 3.3 核对堡垒机资产的 `address`/`name` 与 CMDB IP 是否精确一致；端口映射场景按上面填法调整。
- **终端能打开但报"无法连接 Koko"**：属堡垒机侧终端会话问题（令牌/账号/会话 Cookie），交付已修复；若环境变动后复现，联系管理员核对堡垒机 koko 组件与 API Key 权限。
- **连接被证书拦截**：JumpServer 自签证书时，务必把实例的 **verify_ssl 关闭**，并用 **https** 的 base_url。

## 4. 三项二开的边界（给维护者）

- 二开以**新增目录/文件**为主，对官方代码只动了品牌常量、极少挂载点（SSH 按钮）、4 行顶部导航 CSS 修复；与官方耦合面最小，便于后续跟进上游升级。
- 品牌是**数据配置**不是硬编码，可随时改；钉钉、JumpServer 都是**集成实例**，在集成中心/登录认证里增删改，不动代码。
- 未启用模块（含 AI/OpsPilot 等）仅前端隐藏入口，代码与数据保留，需求变化时可在「应用管理」重新放开。
