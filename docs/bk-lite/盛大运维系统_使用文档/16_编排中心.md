# 盛大运维系统 使用文档 · 16 编排中心

> 模块标识：`workflow`　|　顶部导航入口：**编排中心**
> **适用范围**：预生产环境 `10.10.2.91`（官方最新版）已启用；一期正式环境（`192.168.1.11`，二开镜像）未启用。
> 编排中心用**流程图**把作业执行、HTTP 请求、通知、AI 智能体、人工审批串成自动化流程，支持手工、定时、Webhook、NATS 事件、表单几种触发方式。

> 旧地址 `/workflow-orchestration/*` 与旧接口 `/api/proxy/workflow_orchestration/*` **在新版本中已不存在，访问一律 404**（官方未提供旧地址跳转）。
> 本仓二开基线 `371c89c9`（2026-10-15）早于该提交，源码路径仍是 `web/src/app/workflow-orchestration/`，192.168.1.11 环境仍用旧标识。

## 1. 功能概述

- **首页**：编排总览看板（已发布/启用流程数、今日执行、近 7 天成功率、运行中/排队/失败、待我审批）。
- **流程**：新建/复制/启用/停用/删除流程，画布编排节点。
- **执行记录**：执行列表、执行详情、重新执行、终止。
- **表单**：表单触发入口汇总页，可 **「查看{label}」** 与 **「复制{label}链接」** 直接把表单发给发起人填写。
- **模板市场**（`market`，改名后新增页面）：套用内置/已存模板快速起流程。

**节点类型**（画布可用）：

| 节点 | 分类 | 作用（界面原文摘要） |
|------|------|---------------------|
| **作业执行** | 作业平台 | **「在授权目标上执行用户编写的 Linux 或 Windows 脚本，输出统一 JSON 结果信封」** |
| **HTTP 请求** | 集成 | **「按 Method 与完整 URL 发起 HTTP 请求，运行时做 SSRF 与大小限制」** |
| **对外通知** | 通知 | 发送通知到指定渠道 |
| **AI 智能体** | AI | **「调用当前组织可用的 OpsPilot 智能体处理输入」** |
| **意图识别** | AI | **「使用当前组织可用的 OpsPilot 模型将输入归类到预定义意图」** |
| **人工审批** | 流程控制 | 通过/驳回，驳回进入驳回分支 |

## 2. 入口与前置条件

- 入口：顶部导航选择**名为「编排中心 / Workflow」的应用，进入 `/workflow`**；不要使用旧的 `Workflow Orchestration` 入口（见 §7 FAQ）。
- **前置条件**：
  1. **编排引擎 Conductor 必须已部署**：安装时 `CONDUCTOR_BASE_URL` 为空则本模块根本不会被安装，表现是页面能进、所有接口报 404；
  2. 需要作业执行时，目标机在「作业管理」可用（控制器在线）；
  3. 需要 AI 节点时，OpsPilot 已配置模型与智能体；
  4. 需要通知时，系统管理通知渠道已配；
  5. **流程必须先「发布」再「启用」，才能运行**（界面会提示 **「发布后可启用」**）。

## 4. 核心操作流程（按钮级）

### 4.1 新建并编排一个流程

1. 「流程」→ 点 **「新建流程」**（也可 **「复制流程」**，复制结果提示 **「已复制为新的纯草稿」**）。
2. 填 **「流程名称」**（默认前缀"流程"），进入画布。
3. 从节点面板拖入所需节点（见第 1 节节点类型），把它们用连线串起来。
4. 配置节点参数：
   - **作业执行**：选**执行目标范围**。注意选项约束 **「可选 {min}–{max} 台；节点管理与作业平台不能混选，切换来源会清空已选」**；离线目标会提示 **「离线属于连接状态告警，启动前会再次校验并要求确认。」**
   - **HTTP 请求**：填 Method 与完整 URL（运行时做 SSRF 与大小限制，内网访问可能被拦）。
   - **对外通知**：选通知渠道、填模板；模板 **「支持 .docx 和 .xlsx，模板中可使用受控占位符和循环。」**
   - **AI 节点**：选智能体/模型，定义输入输出。
   - **人工审批**：设置 **「候选审批人」**、**「审批上下文」**；驳回时 **「流程将进入审批驳回分支。」**
5. 保存草稿；有改动未发布时列表会标 **「· 有未发布更改」**。

### 4.2 发布与启用（顺序不能反）

1. **「发布」**：发布当前版本（流程状态显示 **「已发布」**）。
2. **「启用」**：确认 **「启用当前发布版本？」**，成功提示 **「流程已启用」**。
   - 未发布就点启用会提示 **「发布后可启用」**。
3. **「停用」**：确认 **「停用该流程？」**，说明 **「停用后将拒绝新的触发事件，正在执行的流程不受影响。」**，提示 **「流程已停用，不影响历史执行」**。

### 4.3 运行流程（三种方式）

**方式 A：手工运行**
1. 点 **「运行」**（弹窗 **「运行流程 · {name}」**）。
2. **「选择已发布流程并填写运行输入」** 后提交。
3. 校验提示：
   - 未发布：**「请先发布流程」**
   - 未启用：**「请先启用流程」**

**方式 B：定时 / Webhook / NATS 自动触发**
- 由入口自动触发，列表不留手工运行按钮。界面提示：
  - 定时：**「流程将按配置时间自动触发；如需验证，请到编辑页测试定时触发器」**
  - NATS：**「流程由 NATS 事件自动触发；如需验证，请到编辑页监听测试事件」**
  - 其他：**「该流程由定时、Webhook 或 NATS 入口自动触发；请到编辑页查看入口或测试触发器」**
- **验证触发器要去编辑页测**，不要在列表里等。

### 4.4 看执行记录与详情

1. 「执行记录」列表按状态筛选：
   - **「执行中」`RUNNING`**
   - **「等待审批」`WAITING_APPROVAL`**
   - **「成功」`SUCCEEDED`**
   - **「失败」`FAILED`**
   - **「已超时」`TIMED_OUT`**
2. 点进看 **「执行概要」** 与 **「执行详情」**（每个节点输入/输出/耗时）。
3. 作业节点结果看 **「标准输出 / 错误输出 / 作业实例」**。
4. 可 **「重新执行 · {name}」**。

### 4.5 终止执行（谨慎）

1. 点 **「终止本次执行」**，需填 **「终止原因」**。
2. 后果原文：**「后续节点将停止，已发生的外部副作用不会自动回滚。终止原因会写入审计。」**
   > 也就是说：**已经发出去的 HTTP 请求、已经执行的脚本、已发的通知，都不会自动撤销**。

### 4.6 处理待办审批

1. 进 **「待我审批」/「我的待审批」**（无待办显示 **「暂无待处理审批」**）。
2. 看 **「审批上下文」** 后选择：
   - **「通过审批」** → **「已通过审批」**，流程继续走通过分支；
   - **「驳回审批」** → **「已驳回审批」**，流程进入驳回分支。
3. 状态流转：**「等待候选审批人处理」**。

### 4.7 删除流程

- 确认 **「确认删除流程？」**，说明 **「流程本身不可恢复，历史版本快照与执行记录仍保留。」** 删除后提示 **「流程已删除，历史执行仍保留」**。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 流程状态 | 草稿 / 已发布 / 有未发布更改 |
| 发布→启用 | 必须先发布才能启用、才能运行 |
| 停用 | 拒绝新触发，正在执行不受影响 |
| 作业目标 | 节点管理与作业平台不能混选，切换会清空 |
| HTTP 节点 | 运行时做 SSRF 与大小限制 |
| 通知模板 | 支持 .docx/.xlsx，受控占位符与循环 |
| 审批 | 候选审批人 + 审批上下文，驳回走驳回分支 |
| 终止 | 后续节点停止，**外部副作用不回滚** |
| 删除 | 流程不可恢复，历史执行保留 |

## 6. 权限要求

- 编排流程、发布/启用：需编排管理员角色。
- 作业节点受目标团队与作业权限约束（授权目标才能执行）。
- 审批节点按候选审批人授权处理。
- 依赖 AI 节点时需 OpsPilot 权限。

**权限项清单**（官方最新版共 13 项，均挂在应用 `workflow` 下）：

| 页面 | 权限项 |
|------|--------|
| 首页 | `workflow_home-View` |
| 流程 | `workflow-View` / `Add` / `Edit` / `Execute` / `Publish` / `Manage` / `Delete` |
| 模板市场 | `workflow_market-View` / `Add` |
| 执行记录 | `workflow_execution-View` / `Execute` / `Approve` |

> 旧应用 `workflow-orchestration` 名下残留 8 项同类权限（无 `_home` / `_market` / `_execution` 分组前缀）；升级后如果角色仍绑着旧权限项，对新页面无效，需重新授权。

## 7. 常见问题（FAQ）

**Q：点运行提示"请先发布流程"/"请先启用流程"。**
A：顺序是 **保存 → 发布 → 启用 → 运行**。三个前置缺一不可。

**Q：流程改了但运行还是旧逻辑。**
A：改完没重新发布。列表会标 **「· 有未发布更改」**，重新发布后再运行。

**Q：定时/Webhook/NATS 流程在列表里没有"运行"按钮。**
A：设计如此。这类流程由入口自动触发；**验证请去编辑页测试触发器/监听事件**。

**Q：停用后正在跑的流程会不会中断？**
A：不会。**「停用后将拒绝新的触发事件，正在执行的流程不受影响。」**

**Q：终止执行后，已经执行的脚本/发出的通知会撤销吗？**
A：不会。**「已发生的外部副作用不会自动回滚。」** 终止只阻止后续节点，原因会写审计。

**Q：作业节点选目标时之前选的被清空了。**
A：切了目标来源。**「节点管理与作业平台不能混选，切换来源会清空已选」**；离线目标启动前还会再校验确认。

**Q：HTTP 节点访问内网地址失败。**
A：运行时做了 **SSRF 与大小限制**，内网/敏感地址可能被拦。改用允许的目标或走其他节点。

**Q：审批一直卡在"等待审批"。**
A：检查候选审批人是否正确、对应人员是否有权限处理；在「待我审批」里能看到自己的待办。

**Q：导航里点「Workflow Orchestration」直接 404，但另一个「编排中心 / Workflow」是正常的。**
A：正常现象。404 的那条是**改名遗留的幽灵应用**：官方 `3ccc3e336c` 把模块改名为 `workflow` 后，旧路由已从前端镜像中删除，但库里的旧应用记录（`system_mgmt_app` 中 `name=workflow-orchestration`）仍在，而官方初始化脚本只做 upsert、**不会删除代码里已消失的应用**，所以它一直显示。**请使用新入口 `/workflow`**；旧记录需在「应用管理」隐藏或删除（应用被标记为内置时界面拒绝删除，需先放开标记再删），同时注意控制台首页的应用卡片是**每用户一份快照**，逐账号隐藏。

**Q：点进编排中心页面能打开，但所有数据都报错（接口 404）。**
A：后端没装这个 app。本模块**仅在 `.env` 的 `INSTALL_APPS` 包含 `workflow` 时才注册路由**，而 `workflow` 只有在 `CONDUCTOR_BASE_URL` 非空时才会被安装器写入。判定办法：未登录直接请求接口，**返回 401 说明路由存在、404 说明模块未装载**；也可在服务端执行 `docker exec compose-server-1 sh -c 'cd /apps && python manage.py show_urls' | grep /api/v1/workflow/` 看有多少条路由。修复：设好 `CONDUCTOR_BASE_URL` 后重跑安装器（会自动带起 conductor 服务）。

**Q：为什么旧接口前缀是 `workflow_orchestration`、新的是 `workflow`？**
A：因为**数据库表名也一起改了**（`workflow_orchestration_*` → `workflow_*`）。从旧版本升级的环境需要数据迁移，不能只换镜像；这也是本模块升级前必须备份数据库的原因。
