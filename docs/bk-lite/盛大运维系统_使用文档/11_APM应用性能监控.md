# 盛大运维系统 使用文档 · 11 APM（应用性能监控）

> 模块标识：`apm`　|　顶部导航入口：**APM**
> **适用范围**：本模块在预生产环境 `10.10.2.91` 已启用；一期正式环境（`192.168.1.11`）未启用，菜单不可见属预期。
> APM 用 OpenTelemetry 采集应用的调用链（Trace）、指标与错误，提供 RED 指标、服务拓扑、SLO、调用链检索与 APM 告警。
>
> 本篇菜单与按钮文案取自预生产实测菜单与前端源码 `apm/locales`。

---

## 1. 功能概述

- **首页**：6 个 KPI（应用数量/服务数量/活跃告警数/错误请求数等）+ 7 段汇总（健康分布、SLO 概览、实时告警、错误率 TOP5…）。
- **服务**：服务列表、服务拓扑、SLO。
- **探索**：调用链（Trace）、端点、错误。
- **事件**：APM 告警、告警策略。
- **集成**：应用管理、添加接入、接入实例。

---

## 2. 入口与前置条件

- 入口：顶部导航选择「APM」。
- **前置条件**：先完成**应用接入**（集成 → 添加接入），应用上报数据后数分钟内首页才有 KPI。
  - 首次进入首页会看到空态：**「还没有接入任何应用」**，并提示 **「前往集成菜单完成首次接入，数分钟内即可在首页看到 6 个 KPI 与 7 段汇总。」**
- 主机 / Docker 接入需要从平台**下载探针文件**；若提示 **「主机和 Docker 接入需要从平台下载探针文件。当前环境还没有这份文件，请联系管理员完成探针初始化后再试。」**，需管理员先初始化探针。
- APM 告警要发通知，需先在「系统管理 → 通知渠道」配好渠道。

## 4. 核心操作流程（按钮级）

### 4.1 首次接入一个应用（最关键的起步）

1. 「集成 → **添加接入**」。页面说明：**「选择语言与应用，即时生成可复制的 OpenTelemetry 接入配置。」**
2. 先选 **语言**（与部署形态）：
   | 语言 | 接入方式（界面原文要点） |
   |------|------------------------|
   | **Java** | 自动探针；Host 在启动命令加 Agent，Docker 用 `JAVA_TOOL_OPTIONS` 注入，K8s 合并环境变量到 Pod |
   | **Python** | 自动探针，**支持 Django / Flask / FastAPI**；用 `opentelemetry-instrument` 包装启动命令 |
   | **Node.js** | Host 追加启动参数；Docker 写入 Dockerfile 并用 `-e` 注入；K8s 合并环境变量 |
   | **Go** | **手动接入**，生成 OpenTelemetry Provider 示例代码（**「Go SDK 接入指南」**） |
   | **.NET** | 自动探针 + CLR 分析器环境变量 |
   | **OTel（自建 Collector）** | **「转发自建 Collector 链路到平台 OTLP 端点」** |
3. 再选**部署形态**：Host（主机）/ Docker / Kubernetes。系统会给出针对性指引，例如：
   - Java Host：**「在原有 Java 启动命令中加入以下内容，并重启应用。」**
   - Java Docker：**「将 Java Agent 安装命令写入 Dockerfile，通过 JAVA_TOOL_OPTIONS 注入后重新构建、启动容器。」**
   - Java K8s：**「将以下环境变量（含 JAVA_TOOL_OPTIONS）合并到应用 Pod，确保镜像包含 Java Agent 后滚动重启。」**
   - Python Docker：**「将探针安装命令写入 Dockerfile，用 -e 注入环境变量并以 opentelemetry-instrument 启动容器。」**
4. 复制配置并粘贴到你的应用：
   - 点 **「复制 HTTP 上报端点」**（提示「HTTP 上报端点已复制」）
   - 点 **「复制 Shell 接入片段」**（提示「Shell 接入片段已复制」）
   - 或 **「复制 Kubernetes 配置片段」** / **「复制 Go SDK 接入指南」**
   - 复制成功提示 **「已复制 {值}」**，失败提示 **「复制失败，请手动选择并复制」**
5. 重启应用，等待数据上报；回到「集成 → 应用管理」能看到该应用与自动发现的**服务**。

> **SDK 语言识别**：服务卡片上会显示 OpenTelemetry SDK 语言；未识别时提示 **「暂未观测到 SDK 语言」**。运行时不采指标时提示 **「该服务尚未接入运行时指标采集（JVM / Go Runtime 等）」**。

### 4.2 看首页总览

1. 「首页」说明：**「查看应用性能总览、健康分布与待处理告警。」**
2. 关注块：
   - **KPI**：应用数量、服务数量、活跃告警数、错误请求数；
   - **服务健康度分布**（总服务数；无数据显示 **「暂无服务数据」**）；
   - **SLO 概览**（可用性目标；未配置显示 **「暂无 SLO 配置」**，可点 **「前往配置 →」**）；
   - **实时告警**（无告警显示 **「一切正常，无未恢复告警」**）；
   - **服务 TOP5（按错误率）**（无数据显示 **「暂无错误率数据」**）。
3. 应用卡片可直接 **「查看应用详情」**，并显示"应用内 N 个服务 / N 个活跃告警"。

### 4.3 看服务列表 / 拓扑 / SLO

- **服务列表**：空态提示 **「尚无服务上报」**；点服务进 `[serviceId]` 详情。
- **服务拓扑**：查看服务间调用关系与依赖。
- **SLO**：新建/配置 **「可用性目标」**（如 99.9%），列表展示各服务 SLO 达成情况。

### 4.4 查调用链（Trace）

1. 「探索 → 调用链」说明：**「按条件检索近窗 Trace / Span 样本。列表不对账窗内错误率。」**
   > 注意这句：列表是**抽样检索**，不能拿列表条数当错误率统计。
2. 选择 **「调用链查询粒度」**（实体模式：按服务/端点等），可选 **「仅错误」** 过滤。
3. 无样本时提示 **「当前时间窗暂无遥测样本（无流量或尚未上报）」**。
4. 点某条进 `[traceId]` 看完整 Span 瀑布图。

### 4.5 看端点与错误

- **端点**：端点指标来自 **「服务 RED Top endpoint 聚合」**（`RED` = Rate/Errors/Duration）。
- **错误**：按错误类型/服务聚合，点进看样本调用链。

### 4.6 创建 APM 告警策略

1. 「事件 → 策略」→ 点新建（进入 `policies/new`）。页面说明：**「按服务、触发条件和通知方式完整配置策略。」**
2. 填：
   - **「策略名称」**（必填，提示「请输入策略名称」）
   - 选择**服务**与**指标**、**「阈值」**（必填，提示「请输入阈值」）
   - **「通知渠道」** + **「处理人」**（**「从策略所属组织选择处理人」**）
3. 注意两个提示：
   - 若还没有服务：**「请先接入并发现服务，再创建策略。」**
   - 若没有通知渠道：**「当前没有可用通知渠道，可不配置直接创建策略。」**
4. 保存后可在列表**直接启停**；列表说明：**「配置服务指标阈值与通知渠道，列表内可直接启停。」**
5. 无可配置项时显示 **「暂无告警策略」**；搜不到时 **「没有匹配的策略，请调整搜索条件。」**

### 4.7 处置 APM 告警

「事件 → 告警」说明：**「集中查看当前告警与已恢复的历史告警，并追踪每次通知投递结果。」**

- 状态含 **「告警中」/ 已恢复**；通知状态有 **「已通知 / 未通知」**。
- **「通知投递记录」** 可看每次投递；未送达时可 **「通知已进入重投队列」**（重新入队）。
- **「告警指标快照」** 按策略扫描绘制**评估值**与**「当时阈值」**，便于复盘"当时为什么触发"。
- 「配置 → 通知模板」未配渠道时提示 **「未配置通知渠道」**。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 接入方式 | 语言 × 部署形态，生成可复制的 OpenTelemetry 配置 |
| 探针文件 | 主机/Docker 接入依赖平台预置探针，缺失需管理员初始化 |
| HTTP 上报端点 | 复制给应用/Collector 的 OTLP 地址 |
| 调用链列表 | 抽样检索，**不等于**错误率统计 |
| 端点指标 | 来自 RED Top endpoint 聚合 |
| SLO | 可用性目标（如 99.9%） |
| 策略必需 | 名称 + 阈值；无渠道也可先建 |
| 通知投递 | 有投递记录与重投队列 |

## 6. 权限要求

- 查看 APM：一般运维/研发角色，受应用/团队数据权限约束。
- 接入应用、创建告警策略：需 APM 管理员或应用负责人角色。
- 通知渠道在系统管理维护。

## 7. 常见问题（FAQ）

**Q：首页一直是"还没有接入任何应用"。**
A：还没完成接入。去「集成 → 添加接入」按语言/部署形态生成配置并粘到应用里，重启后等数分钟上报。

**Q：接入配置复制不了/探针下载失败。**
A：提示"当前环境还没有这份文件，请联系管理员完成探针初始化"时，需管理员先初始化探针；复制失败可手动选中复制（「复制失败，请手动选择并复制」）。

**Q：创建策略时提示"请先接入并发现服务"。**
A：APM 还没有自动发现服务，先完成接入并等数据上报。

**Q：没有通知渠道能建策略吗？**
A：可以。原文 **「当前没有可用通知渠道，可不配置直接创建策略。」** 但告警不会外发，建议后续补配。

**Q：调用链列表条数很少，是丢数据了吗？**
A：不是。调用链是**近窗样本检索**，界面明确说明"列表不对账窗内错误率"；看错误率请用服务/端点 RED 指标。

**Q：告警里看不到"当时为什么触发"。**
A：点告警的**指标快照**，会按策略扫描画出评估值与**当时阈值**。

**Q：通知没发出去。**
A：看「通知投递记录」；失败可重新入队（提示"通知已进入重投队列"），并检查系统管理通知渠道连通性。
