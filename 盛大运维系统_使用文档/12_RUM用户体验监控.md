# 盛大运维系统 使用文档 · 12 RUM（用户体验监控）

> 模块标识：`rum`　|　顶部导航入口：**RUM**
> **适用范围**：预生产环境 `10.10.2.91` 已启用；一期正式环境（`192.168.1.11`）未启用，菜单不可见属预期。
> RUM 采集浏览器端真实用户体验：会话、页面性能（Core Web Vitals）、JS 错误、部署版本对比、转化漏斗与 RUM 告警。前端通过 **Faro SDK** 上报。
>
> 本篇菜单与按钮文案取自预生产实测菜单与前端源码 `rum/locales`。

---

## 1. 功能概述

- **体验**：会话（含会话回放）、视图与性能、转化漏斗。
- **质量**：错误追踪、部署追踪（按发布版本对比）。
- **事件**：RUM 告警、告警策略。
- **集成**：应用（创建/浏览）、接入（Origin 与 SDK 配置）。
- **数据治理**：合规删除。

---

## 2. 入口与前置条件

- 入口：顶部导航选择「RUM」。
- **前置条件（顺序不能反）**：
  1. 「集成 → 应用」**创建应用**（填应用名 + 允许的浏览器 Origin），创建后立即签发 **Browser Key**；
  2. 「集成 → 接入」按指引把 **Faro SDK** 注入前端页面；
  3. 页面产生真实流量后，体验/质量才有数据。
- 可能出现的能力提示：
  - **「RUM 控制面暂不可用，应用目录可能为空。」** / **「无法读取应用列表与接入配置，请检查 RUM controller 连接。」** → 后端控制面异常，联系管理员；
  - **「体验分析暂不可用（观测仓未配置或不可达）。仍可管理应用与接入配置。」** → 观测存储未就绪，应用与接入仍可配。

## 4. 核心操作流程（按钮级）

### 4.1 创建 RUM 应用（第一步）

1. 「集成 → 应用」→ 点 **「新建应用」**。
2. 页面说明：**「填写应用名与允许的浏览器 Origin；创建后立即签发 Browser Key。」**
3. 填：
   - **应用名**：规则原文 **「1–80 个字母、数字、点、下划线、冒号或短横线，以字母或数字开头；须与 SDK app.name 完全一致。」**——**必须与前端 SDK 里配的名字一模一样**，否则数据对不上。
   - **允许的浏览器 Origin**：**「精确填写协议、主机和可选端口。其他 Origin 会被拒绝；这仍是滥用控制，Browser Key 不可省略。」** 可 **「添加 Origin」/「删除 Origin」**。
4. 点 **「创建」**；未填完整会提示 **「请填写应用名称与至少一个 Origin」**。
5. **Browser Key 只显示一次**：提示 **「请立即复制；此 Token 只显示一次。」** 务必当场保存到配置里，丢了只能重新签发。

### 4.2 接入前端（Faro SDK）

1. 「集成 → 接入」：列表显示 **「接入状态」**（`已接入 / 未接入`），可按状态筛选。
2. 点某应用的 **「接入」** 进入 `setup/[name]`，按步骤 **「应用与 Origin」** 配置：
   - 核对/维护 **「允许的 Origin」**；
   - 复制 SDK 初始化片段（含 Browser Key）到你的前端工程。
3. 部署后刷新页面，接入状态转为 **「已接入」**。
4. 若应用列表为空：**「还没有需要接入的应用」**，提示 **「先在应用里创建一个，再回到这里配置 Origin 与 SDK。」**

> 额度：超出上报预算后 **「网关拒绝这一分钟内的新上报」**；保存 Origin **不会改动已保存的预算**。

### 4.3 看会话与回放

1. 「体验 → 会话」：列表按 **「按会话」/「按错误率」** 排序；可搜索应用。
2. **错误率口径**：**「错误率 = 出错会话 / 总会话」**。
3. 点进 `[sessionId]` 看会话详情；点 **「会话回放」**（`/replay`）还原用户操作过程。

### 4.4 视图与性能（Core Web Vitals）

- 「体验 → 视图与性能」说明：**「按路由或发布版本查看 Core Web Vitals。」**
- 关键指标：**LCP**（最大内容绘制）、**CLS**（累积布局偏移）等；可按**路由**或**版本**对比。
- 首页 KPI 含 **「差体验应用」**、**「会话」**、**「最差 LCP」**。

### 4.5 转化漏斗

1. 「体验 → 转化漏斗」→ 新建 **「路径」**。
2. 空态提示 **「创建一条路径，用现有浏览数据测算转化。」**
3. 支持 **「复制」/「删除」** 漏斗；删除需确认 **「确认删除漏斗「{name}」？」**
4. 点进 `[id]` 看各步骤转化与流失。

### 4.6 错误追踪与部署追踪

- **错误追踪**：按错误指纹聚合；点进 `[detail]` 看 **「错误详情」**、堆栈（点 **「复制堆栈」**，提示「已复制完整堆栈」）、**「采样最近发生的异常会话上下文」**。
- **部署追踪**：按**发布版本**对比错误率/性能变化，快速定位"哪次发布引入的问题"。

### 4.7 配置 RUM 告警策略

1. 「事件 → 策略」→ **「新建策略」**（可 **「编辑策略」/「删除」**，删除确认 **「确认删除该策略？」**）。
2. 设监控指标、阈值与通知方式，保存。
3. 无策略时显示 **「还没有告警策略」**。
4. 「事件 → 告警」查看触发的 RUM 告警并处置。

### 4.8 数据治理：合规删除

- 「数据治理 → 合规删除」：按合规要求删除指定会话/数据，用于满足隐私合规（如用户要求删除其浏览记录）。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 应用名 | 1–80 位字母数字点/下划线/冒号/短横线，**须与 SDK app.name 一致** |
| Origin | 精确协议+主机+端口，不匹配会被拒 |
| Browser Key | 创建时**只显示一次**，立即保存 |
| 错误率 | 出错会话 / 总会话 |
| Core Web Vitals | LCP、CLS 等，按路由/版本看 |
| 接入状态 | 已接入 / 未接入 |
| 上报预算 | 超预算网关拒绝该分钟新上报 |

## 6. 权限要求

- 浏览会话/错误/性能：研发/运维角色，受应用与团队数据权限约束。
- 创建应用、签发 Browser Key、改 Origin：需 RUM 管理员或应用负责人。
- 合规删除属高敏操作，建议单独授权并留审计。

## 7. 常见问题（FAQ）

**Q：接入状态一直是"未接入"。**
A：① SDK 未注入或未部署；② 应用名与 SDK `app.name` 不完全一致；③ Origin 与实际访问域名不匹配（协议/端口都要精确）。三项任一不符都会没有数据。

**Q：Browser Key 找不到了。**
A：设计上**只显示一次**。需重新签发（旧 Key 作废），再更新前端配置。

**Q：有应用但会话/错误都是空的。**
A：还没有真实流量，或观测仓未就绪（提示"体验分析暂不可用（观测仓未配置或不可达）"）。先确认前端上报成功。

**Q：应用列表打不开/为空。**
A：提示"RUM 控制面暂不可用"或"请检查 RUM controller 连接"时属后端问题，联系管理员。

**Q：错误率和我自己在浏览器统计的不一致。**
A：RUM 口径是**出错会话/总会话**，按会话去重，不是按请求数。

**Q：上报被限流。**
A：触发了预算上限，**该分钟内的新上报会被网关拒绝**。评估是否需要调整预算；改 Origin 不会自动改预算。

**Q：想查"某次发版后变差"。**
A：用「部署追踪」按发布版本对比错误率与 Core Web Vitals。
