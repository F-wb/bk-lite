# 盛大运维系统 使用文档 · 08 补丁管理

> 模块标识：`patch_mgmt`　|　顶部导航入口：**补丁管理**
> 补丁管理用于跟踪补丁、评估主机合规、批量安装缺失补丁。目标主机来自 CMDB；**安装执行固定走 Ansible 执行链路**（界面提示 **「补丁目标固定走 Ansible 执行链路(无需选择)」**）。
>
> 本篇按钮与提示文案取自前端源码 `patch-manager/locales`。

---

## 1. 功能概述

- **首页**：补丁概览（合规/风险态势）。
- **风险治理**：待治理风险 + 执行记录。
- **补丁库**：浏览/筛选补丁。
- **基线管理**：定义"主机应满足的补丁/包版本要求"。
- **目标管理**：纳管需打补丁的主机。
- **设置**：补丁源、扫描设置。

---

## 2. 入口与前置条件

- 入口：顶部导航选择「补丁管理」。
- **前置条件**：
  1. CMDB 有主机且被纳管为补丁目标；
  2. 目标机可被 Ansible 执行链路连上（连通性、凭据）；
  3. 补丁源已配置并**同步**（否则补丁库为空）；
  4. 已建**基线**（否则界面显示 **「未配置基线」**，无法判定合规）。

## 4. 核心操作流程（按钮级）

### 4.1 配置补丁源并同步

1. 「设置 → 补丁源」→ 新建 **「补丁源」**，填 **「补丁源名称」**、**「补丁源类型」**。
2. **源类型**（界面枚举）：
   - Linux：**`yum 源` / `dnf 源` / `apt 源`**
   - Windows：**`Windows 源`**（WSUS）
   - 另有 **`Linux 源`** 汇总入口。
3. 点 **「测试连接」** 验证可达。
4. 点 **「同步」** 拉取补丁元数据，完成提示 **「同步完成」**。
5. 「补丁库」可看到 **「补丁总数」**，支持按 **「补丁标题/补丁类型/严重级别」** 筛选；补丁类型有 **`安全补丁` / `通用补丁`**。

> **补丁库为空**时先查：源是否同步、类型是否匹配目标 OS、连接是否正常。

### 4.2 纳管补丁目标

1. 「目标管理」→ 点 **「添加主机」**（从 CMDB 选）。
2. 列表字段：**「目标名称」「目标IP」「系统版本」「Windows版本」**、状态（含 **`未检测`**）。
3. 对目标做连通性检测；不可达会标记异常。
4. 注意提示 **「版本未映射」**（`blockedUnmapped`）：目标 OS 版本没映射到补丁源版本时，相关补丁不会正确匹配，需补映射或调整源。

### 4.3 新建合规基线

1. 「基线管理」→ 点 **「新建基线」**。
2. 界面说明：**「定义主机应满足的补丁/包版本要求。」**
3. 填基线名称、适用平台，选择**必装补丁/包版本**（可含 **「包版本」「版本别名」**）。
4. 保存后可版本管理；基线是对目标做合规评估的标准。

### 4.4 扫描并评估合规

1. 「设置 → 扫描设置」配扫描策略：频率、范围、时区、通知（含 **「失败目标阈值」**：**「失败目标数达到该值时通知；留空则任一失败即通知」**）。
2. 执行 **「补丁扫描」**：建 **「扫描任务名称」** → 运行（注意：**「仅等待中的任务可执行」**）。
3. 结果看 **「扫描结果」**（`已安装 / 可安装 / 已安装跳过 / 待重启警告` 等）与 **「扫描结果分布」**、**「补丁严重级别分布」**。
4. 「扫描记录」看历史、**「最近扫描状态」「扫描时间」**。

### 4.5 治理风险并批量安装

1. 「风险治理 → 待治理风险」查看缺口。首页 KPI 有：
   **「高危缺失补丁」「受影响目标」「待重启目标」「失败安装任务」**。
2. 勾选补丁 + 目标 → 发起 **「补丁安装」**：填 **「安装任务名称」**。
3. **重启策略**（关键，三种）：
   - **`不重启`**
   - **`安装后立即重启`**
   - **`指定时间重启`** → 之后可 **「重新指定时间」**（提示「已重新指定重启时间」），看 **「计划时间/执行时间/重启时间」**
4. 执行后跟踪每台主机状态（成功/失败/待重启）；失败有错误日志。任务队列中 **「仅等待中的任务可执行」**。
5. 「执行记录」留存，失败任务有 **「失败目标阈值」** 通知。

### 4.6 看整体态势（首页）

- 合规率、安装趋势、**「补丁严重级别分布」「扫描结果分布」**，支持时间范围切换。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 补丁源类型 | yum / dnf / apt / Windows(WSUS) |
| 补丁类型 | 安全补丁 / 通用补丁 |
| 基线 | 主机应满足的补丁/包版本要求，可版本化 |
| 扫描结果 | 已安装 / 可安装 / 已安装跳过 / 待重启警告 |
| 重启策略 | 不重启 / 安装后立即重启 / 指定时间重启 |
| 版本未映射 | OS 版本与补丁源版本未对应，需补映射 |
| 失败目标阈值 | 达到该值才通知；留空任一失败即通知 |
| 执行链路 | 固定走 Ansible（无需选择） |

---

## 6. 权限要求

- 批量安装补丁属**高风险变更**，建议"补丁/系统管理员"+ 变更审批。
- 目标执行受团队归属与 Ansible 执行权限约束。
- 普通运维可查合规态势与本机缺失补丁。

## 7. 常见问题（FAQ）

**Q：补丁库是空的。**
A：补丁源没同步或类型不匹配。先在「补丁源」点 **「测试连接」→「同步」**，确认类型（yum/dnf/apt/Windows）与目标 OS 一致。

**Q：主机显示不合规但没有缺失补丁。**
A：① 补丁库未同步；② 基线未建或未含相关补丁（界面可能显示 **「未配置基线」**）；③ 目标 **「版本未映射」**。逐项处理后重新扫描。

**Q：批量安装失败。**
A：① 目标连通性/凭据（先做检测）；② 包管理器/WSUS 可用；③ 执行记录看该主机错误；④ 补丁安装固定走 Ansible，确认执行链路正常。

**Q：点了执行没反应/按钮灰。**
A：**「仅等待中的任务可执行」**——该任务不在等待状态（已执行/进行中/已完成），到执行记录核对状态。

**Q：打了补丁还要重启。**
A：状态"待重启警告/待重启目标"表示需重启才最终生效。按重启策略安排；若选了"指定时间重启"，可用 **「重新指定时间」** 调整。

**Q：Windows 主机没补丁。**
A：配置 **「Windows 源」**（WSUS）并同步；补丁库也可手动写入 Windows 补丁。

**Q：失败通知太吵。**
A：设 **「失败目标阈值」**，只有失败数达到阈值才通知。
