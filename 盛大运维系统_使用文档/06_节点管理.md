# 盛大运维系统 使用文档 · 06 节点管理

> 模块标识：`node_mgmt`　|　顶部导航入口：**节点管理**
> 节点管理是"采集与执行能力的落地层"。界面定义原文：**「节点是控制器和托管组件运行的环境，可以是一个主机或容器。平台依托节点上的控制器，对节点进行管理，并统一调控被托管组件的运行。」**
> 监控指标、日志、作业执行、补丁安装都依赖这里的控制器（Sidecar）与采集器（Collector）在线。
>
> 本篇按钮与提示文案取自前端源码 `node-manager/locales`。

---

## 1. 功能概述

- **云区域**：多云/多区域划分，下设节点、环境、变量。界面说明：**「云区域环境中通过在代理主机或 K8s 集群上运行的 Nats Executor 和 Stargazer 组件，实现与平台的通信。」**
- **组件库**：采集器相关包管理与版本。
- **控制器**：作业执行侧的 Controller（Sidecar）安装与包管理。
- **安装运维**：远程/手动安装、更新、卸载、启停、重启。
- **状态**：在线/离线/异常、版本、架构。

---

## 2. 入口与前置条件

- 入口：顶部导航选择「节点管理」。
- **前置条件**：
  1. 目标机凭据已建（SSH / WinRM），在「系统管理 → 凭据管理」；
  2. 平台与目标机网络可达（跨云需配代理）；
  3. **远程安装需要一个"默认节点"**：界面明确要求 **「远程安装组件需要使用默认节点进行相关安装包的推送，需要选择 nas executor 状态正常的节点。」** 卸载同理（**「卸载控制器需要使用默认节点，需要选择 nas executor 状态正常的节点」**）。
  4. 目标机 OS/架构要有匹配的安装包，否则提示 **「该节点操作系统/架构暂无可用包，无法安装。」** 或 **「没有匹配的控制器版本」**。

## 4. 核心操作流程（按钮级）

### 4.1 建云区域与环境

1. 「云区域」→ 新建，填区域名称与**代理地址/端口**（跨云或不可直连时）。
2. 「环境」区分同区域下不同环境；「变量」维护可被下发引用的区域级变量。
3. 云区域依赖代理主机/K8s 上的 **Nats Executor + Stargazer** 与平台通信（见 1 节原文），代理状态异常会影响该区域全部节点。

### 4.2 安装控制器（Sidecar）——两种方式

在「云区域 → 节点」对目标节点点 **「安装控制器」**，弹窗先选 **「安装方式」**：

**方式 A：远程安装**
- 界面说明：**「远程安装需要提供主机相关登录信息，进行远程安装控制器（Sidecar）」**
- 需选择远程安装用的 **Nas Executor 版本**（**「请选择远程安装的 Nas Executor 的版本」**）和**默认节点**。
- Linux 走 SSH；**Windows 走 WinRM**，界面说明：**「通过同云区域的 Ansible Executor 和 WinRM 下发原生安装程序。支持 Server 2016、PowerShell 5.1 及以上，默认 HTTPS/5986 和 NTLM，也可显式选择 HTTP/5985；证书校验仅在 HTTPS 下可用，默认关闭。」**
- **WinRM 三个硬约束**：
  - **端口与协议必须匹配**：**「HTTPS 不能使用 5985，HTTP 不能使用 5986」**；
  - 选了 HTTP 会弹警告 **「仅限可信内网。HTTP 明文传输管理员认证材料和安装会话信息，被动旁路即可截获。安装服务 URL 仍走 HTTPS。」**
  - 关闭证书校验警告：**「仅限可信内网环境使用。关闭后无法确认目标主机及平台服务身份，Windows 登录凭据和远程操作数据可能被中间人截获或篡改。」**

**方式 B：手动安装**
- 界面说明：**「手动安装，需要按照安装步骤前往主机进行手动操作安装控制器」**
- 在目标机上执行「安装指引」里的步骤；可先点 **「下载安装包」**。
- 下载页提供指引：**「1、根据节点名称和组织，选择适用的版本下载控制器安装包和配置文件模板」**，并有 **「安装指南」**。

安装过程中提示 **「仍有节点正在安装中，返回后可在列表中查看安装正常的节点。」**——不必等页面转圈，可回列表看结果。

### 4.3 采集器（Collector）的安装与生命周期

- 节点详情里对采集器点 **「安装/更新组件」**；版本要与 OS/架构匹配：
  - 界面提示 **「请选择当前操作系统和 CPU 架构（{architecture}）对应的控制器版本」**；
  - 架构缺失时：**「所选节点缺少 CPU 架构，请等待节点上报或先补齐节点架构后再操作组件。」**
- 常用动作：**「启动组件」「停止组件」「重启组件」「卸载」**；重启有确认 **「您确定要重新启动这些收集器吗？」**
- 状态：`已安装 / 未安装 / 安装 / 卸载中`。

### 4.4 卸载控制器

1. 节点操作点 **「卸载控制器」**，确认 **「确定要卸载这些控制器吗？」**
2. 需选默认节点（nas executor 正常）。
3. 卸载中提示 **「仍有节点正在卸载中，返回后可在列表中查看最新的节点。」**；成功后提示 **「卸载成功」**。

### 4.5 批量换组织

- 列表支持多选后批量改归属，提示 **「将为已选择的 {count} 个节点统一替换所属组织。」**

### 4.6 包管理与版本

- 「组件库 → 包管理」「控制器 → 包管理」：上传包、维护版本与架构、提供需鉴权下载。
- 升级时按节点 OS/架构匹配推荐版本，避免把 x86 包推给 ARM。

## 5. 字段与配置项说明（速查）

| 项 | 说明 |
|----|------|
| 节点定义 | 控制器与托管组件运行的环境（主机或容器） |
| 云区域通信 | 依赖 Nats Executor + Stargazer |
| 远程安装默认节点 | 必须是 **nas executor 状态正常** 的节点 |
| WinRM 版本 | Server 2016+、PowerShell 5.1+ |
| WinRM 默认 | HTTPS/5986 + NTLM；HTTP/5985 仅可信内网 |
| HTTPS/HTTP 端口 | HTTPS≠5985，HTTP≠5986 |
| 证书校验 | 仅 HTTPS 下可用，默认关闭 |
| 采集器版本 | 必须匹配目标 OS 与 CPU 架构 |

---

## 6. 权限要求

- 安装/卸载/启停控制器与采集器、管包与版本：**基础设施操作**，建议仅"平台/节点管理员"。
- 普通运维可查看节点状态，判断"我的机器采集是否正常"。
- 目标机凭据在系统管理维护，注意范围控制。

## 7. 常见问题（FAQ）

**Q：安装控制器失败，报连不上目标机。**
A：① 目标机 SSH/WinRM 可达、端口开放；② 凭据正确；③ 是否需经云区域代理；④ **默认节点是否为 nas executor 正常状态**（这是最常见原因）；⑤ 看安装会话详细错误。

**Q：提示"没有匹配的控制器版本"。**
A：目标机 OS/架构没有可用安装包。先到「控制器 → 包管理」上传匹配架构的包；或等节点上报 CPU 架构后再试。

**Q：Windows 安装报端口/协议不匹配。**
A：HTTPS 必须配 5986，HTTP 必须配 5985，选错会直接报 **「WinRM 协议与端口不匹配」**。

**Q：Windows 装上了但连不稳/有中间人风险提示。**
A：优先用 HTTPS/5986 并开启证书校验；若用 HTTP/5985 仅在可信内网，且明确警告"明文传输认证材料"。

**Q：节点显示离线。**
A：采集/控制器进程停了或心跳断。确认目标机组件在跑（异常自动重启），再查网络、Token 是否过期、云区域代理是否正常。

**Q：监控/日志没数据，是不是这里的问题？**
A：很可能。这里是采集链路底座——先确认目标机控制器在线、采集器已装、采集模块已推送，再回监控/日志侧查配置。

**Q：要升级 ARM 机器的采集器。**
A：包管理里选 **ARM 架构**的包，升级推荐会按架构匹配，避免推错包。
